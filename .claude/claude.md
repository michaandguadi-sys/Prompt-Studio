# MAPINSY

## Mission

Mapinsy is not an AI map generator.

Mapinsy is the world's best AI Map Story Builder.

Everything we build must help creators communicate geographic stories more beautifully, clearly and emotionally.

Our users should feel like they are directing a Netflix documentary, not operating GIS software.

Our north star is:

Story first.
Maps second.
Technology third.

---

# Product Philosophy

We never build features.

We build storytelling tools.

Every interaction should increase:

• Story clarity
• Emotional impact
• Ease of use
• Creative confidence
• Professional output

Never optimize for adding functionality.

Optimize for reducing friction.

The best feature is the one users never have to think about.

---

# Quality Standard

Every feature should feel launch-ready.

Never ship "good enough."

Everything should feel intentional.

If something feels average,
keep improving.

---

# Engineering Philosophy

Never assume.

Always verify.

Inspect existing implementation before coding.

Run the application.

Click every button.

Hover every element.

Resize the browser.

Test mobile.

Test keyboard navigation.

Test empty states.

Test loading.

Test errors.

Never trust code without verifying behavior.

---

# Product Owner Mindset

Before implementing anything ask:

Why does this exist?

Who benefits?

Does it improve storytelling?

Can this be simpler?

Can this be removed?

Can this be automated?

Less is usually better.

---

# UX Rules

The product should never overwhelm.

Every screen should answer exactly one question.

Every animation should have a purpose.

Every transition should reduce cognitive load.

Every interaction should reinforce confidence.

---

# Animation Philosophy

Motion should communicate.

Not decorate.

Camera movement should feel cinematic.

Movement should guide attention.

Movement should never distract.

Always prefer slower, intentional movement over constant animation.

---

# Visual Language

One project = one visual identity.

Do not randomly change:

• colors
• typography
• line styles
• camera behavior
• label systems

Consistency creates professionalism.

---

# Code Quality

Prefer:

Simple architecture

Reusable components

Readable code

Small functions

Predictable state

# Mapinsy Principle

Everything should make the creator feel:

"This understands my story."

Not:

"This generated a map."


# Story Intelligence

Every generated animation should answer these questions:

What is the viewer supposed to understand?

What should they feel?

What should they remember?

What geographic context is necessary?

What information is unnecessary?

If removing an element makes the story clearer,

remove it.

Clarity beats complexity.

Always.
